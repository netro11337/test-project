# Ozon / Wildberries — параллельная сборка корзин

GUI на Python + Tkinter: выбираете маркетплейс, задаёте число потоков, каждому
потоку — свой список SKU. Каждый поток работает в **отдельном браузере с
отдельной сессией**, то есть собирает **свою отдельную корзину**, и по
завершении отдаёт ссылку с кнопки «Поделиться».

```
1 поток = 1 браузер = 1 сессия = 1 корзина = 1 ссылка
```

## Запуск

**Windows — двойным кликом по `Запуск.bat`.** Он сам находит Python (сначала
лаунчер `py`, потом `python`), при первом запуске доставляет библиотеки и
открывает программу. Чёрное окно рядом закрывать не нужно — в него идёт
журнал; если что-то падает, окно остаётся открытым с текстом ошибки.

Вручную или на других системах:

```bash
pip install -r requirements.txt
python main.py
```

Нужен установленный Chrome. Драйвер подтягивается автоматически
(`webdriver-manager`, с откатом на встроенный Selenium Manager).

## Как пользоваться

1. Вверху выберите **маркетплейс** — Ozon или Wildberries. Выбор действует на
   весь запуск: все потоки идут в один магазин. Нужны обе площадки — запустите
   сборку дважды, переключив тумблер.
2. Укажите число потоков — под каждый появится вкладка «Поток N».
3. Вставьте SKU: в общее поле и нажмите **«Разбить по потокам»**, либо руками
   по вкладкам. Принимаются запятые, переносы строк, точки с запятой и полные
   ссылки на товар обоих магазинов:
   - `https://www.ozon.ru/product/tovar-1234567890/`
   - `https://www.wildberries.ru/catalog/1234567890/detail.aspx`
4. **«Собрать корзины»** — в таблице справа живой статус каждого потока, в
   логе — каждый товар с временем.
5. По готовности: **«Копировать ссылку»**, **«Копировать все ссылки»** или
   **«Открыть корзину»** — поднимает видимый браузер именно с этой корзиной.

## Ссылка на корзину

Собрав корзину, поток открывает её и жмёт **«Поделиться»** — ту самую кнопку на
странице корзины. Полученная ссылка попадает в таблицу; её можно отправлять
кому угодно, она не требует вашей сессии.

Кнопка выглядит по-разному, и это учтено:

- **Ozon** — подписана текстом, ищется по нему.
- **Wildberries** — иконка без подписи, в строке магазина рядом с «сердечком» и
  корзиной удаления. Ищется перебором: `aria-label` → `title` → `data-testid` →
  класс → `data-tag` → сама SVG-иконка. Сработавший селектор пишется в лог —
  по нему видно, какой вариант ещё живой, если вёрстка поедет.

На Ozon шага два, и это учтено: иконка открывает окно «Поделиться списком» со
списком товаров, и только вторая кнопка внутри окна («Поделиться · N товаров»)
создаёт ссылку. После неё магазин показывает «Ссылка скопирована» и кладёт её
в буфер обмена.

Ссылка достаётся несколькими способами, первый сработавший выигрывает
(`cart.py`):

| Способ | Что читаем |
|---|---|
| `input` | поле со ссылкой в открывшемся окне |
| `anchor` | `href` ссылки в этом окне |
| `text` | текст окна, если ссылка просто напечатана |
| `clipboard` | буфер обмена браузера (права выдаются через CDP, перед кликом кладём метку, чтобы не принять за ссылку старое содержимое) |
| `os_clipboard` | системный буфер обмена — читается уже самим приложением, если браузер ссылку не отдал |

Если магазин показал «Ссылка скопирована», а прочитать её не удалось ни одним
способом, программа так и напишет: ссылка в буфере обмена, вставьте её через
Ctrl+V.

## Очистка корзины

После того как ссылка получена, корзина очищается — иначе на следующем круге
товары накопятся и попадут в новую ссылку (профили сохраняются между
запусками). Отключается галкой **«Очищать корзину после ссылки»**.

Порядок важен: сначала ссылка, потом очистка. Успех подтверждается повторным
подсчётом позиций — «очистил» не должно оказаться такой же неправдой, какой
однажды было «добавил». Если очистить не вышло, программа прямо предупредит,
что следующий круг начнётся не с пустой корзины.

⚠️ В режиме «Работать в моём Chrome» очистка удаляет товары из **вашей
настоящей корзины** в аккаунте. Если это не то, что нужно, снимите галку.

Ссылка проверяется на принадлежность домену выбранного магазина — поток не
отдаст ссылку Ozon, когда вы собирали корзину на WB.

Перед кликом отмечается чекбокс **«Все»**, если он есть: на WB кнопка шарит
выделенные товары, и со снятой галкой можно получить ссылку на половину
корзины. Если кнопок «Поделиться» на странице несколько — значит в корзине
товары разных магазинов, и в лог уходит предупреждение, что ссылка охватит
только первый.

Если ссылку получить не удалось — в таблице **⚠** и обычный адрес корзины, а в
логе причина. Корзина при этом собрана: её видно кнопкой **«Открыть корзину»**,
которая поднимает видимый Chrome на профиле нужного потока. Получение ссылки
можно вообще выключить чекбоксом **«Ссылка "Поделиться"»**.

## Профили и сессии

Профили Chrome лежат в `~/.cart_bot/profiles/<маркетплейс>/thread-N` и разведены
по магазинам: у корзины Ozon и корзины WB в потоке 1 разные сессии. Профили
переживают закрытие приложения — при следующем запуске поток вернётся в свою
корзину.

Если корзины нужны в вашем аккаунте, залогиньтесь один раз в каждом профиле
(кнопка «Открыть корзину» → вход) — сессия сохранится.

## Оптимизации скорости

| Приём | Где |
|---|---|
| `--headless=new` | `driver.py` |
| Картинки, шрифты, видео отключены (флаг Blink + prefs + CDP `setBlockedURLs`) | `driver.py` |
| Аналитика/трекеры зарезаны по URL-маскам | `config.py` |
| `page_load_strategy = "eager"` — не ждём «хвост» загрузки | `driver.py` |
| Прямой переход на карточку товара вместо поиска | `markets.py` |
| Селекторы по `data-widget` / классам вместо текста | `markets.py` |
| Таймауты ≤ 5 с, опрос каждые 0.1 с | `config.py` |
| Единственный `sleep` — 0.35 с после подтверждения добавления | `worker.py` |
| С карточки сразу на карточку, без возврата на главную | `worker.py` |
| Пул потоков, драйвер живёт весь батч, а не поднимается на каждый SKU | `runner.py` |

Таймауты, паузу, число ретраев и параллельность можно менять прямо в шапке GUI.

## Почему клик повторяется

Кнопка «В корзину» появляется в разметке раньше, чем к ней привязывается
обработчик нажатия. Клик по такой кнопке проходит впустую: визуально всё на
месте, но ничего не происходит. Поэтому:

- после загрузки карточки выдерживается пауза (**«Пауза до клика, с»**,
  по умолчанию 2 с);
- клик повторяется до **«Кликов»** раз (по умолчанию 3), и **между попытками
  кнопка ищется заново** — магазин её перерисовывает, и старая ссылка на
  элемент становится нерабочей;
- цикл останавливается сразу, как добавление подтвердилось: лишние клики
  положили бы в корзину второй экземпляр;
- в логе видно, с какой попытки получилось.

## Исходы по каждому SKU

`added` · `already` (уже в корзине) · `out_of_stock` · `not_found` ·
`blocked` (антибот-проверка) · `error`.

Ретраи делаются только для `error` и `blocked` — исходы, которые могут
починиться при повторе. При `blocked` поток останавливается: проверка бьёт по
всей сессии, и дальнейшие попытки только копят ошибки, не портя другие корзины.

## Структура

```
main.py              точка входа
cart_bot/
  markets.py         адреса и селекторы Ozon и Wildberries — вся разница тут
  config.py          настройки скорости, пути профилей, маски блокировки
  skus.py            разбор SKU (включая ссылки обоих магазинов) и раскладка
  driver.py          фабрика Chrome со всеми оптимизациями
  worker.py          добавление одного SKU + распознавание исходов
  cart.py            страница корзины: подсчёт позиций и кнопка «Поделиться»
  runner.py          ThreadPoolExecutor, события в GUI, открытие корзины
  gui.py             Tkinter
tests/test_skus.py   тесты разбора и раскладки
tests/test_cart.py   тесты извлечения ссылки и перебора селекторов кнопки
```

```bash
python -m unittest discover -s tests
```

## Добавить ещё маркетплейс

Опишите его в `markets.py` — адреса, селекторы кнопок и корзины — и добавьте в
`MARKETS`. Остальной код (потоки, разбор SKU, статусы, ссылки) трогать не нужно,
в GUI автоматически появится ещё одна радиокнопка.

## Работа в браузерах Chrome с окнами

Режим **«Работать в моём Chrome»** ведёт обычные окна Chrome вместо скрытых
рабочих браузеров. Запускать ничего вручную не нужно: программа сама открывает
столько окон, сколько задано потоков (порты 9222, 9223, … и отдельный профиль
на каждое), и работает в них параллельно.

`Chrome с отладкой.bat` остаётся запасным путём, если автозапуск не сработал.

## Пять потоков параллельно: как не смешать корзины

Корзина магазина живёт на **сервере и привязана к аккаунту**, а не к браузеру.
Отсюда правило:

| Что в окнах | Корзины | Параллельно? |
|---|---|---|
| Один аккаунт во всех | одна общая | нет, смешает товары |
| Разные аккаунты | разные | да |
| **Вход не выполнен** | **разные, по кукам профиля** | **да** |

Третья строка и есть рабочий вариант для пяти потоков. Важно не путать её с
инкогнито: **профиль без входа — обычный постоянный профиль**, он хранит куки,
живёт от запуска к запуску и со временем «обживается». Инкогнито не хранит
ничего, поэтому антибот к нему придирается — а профиль без входа выглядит как
обычный незалогиненный посетитель, который к вам возвращается.

Итого для параллельной работы: **«Браузеров» = 5, вход в аккаунт не выполнять**.

Программа проверяет это сама. После разогрева каждое окно пишет в лог, выполнен
ли в нём вход, и если залогиненных окон окажется больше одного — выдаёт
предупреждение, что корзина у них общая. Плюс после сборки сверяет: если в
корзине больше позиций, чем выдано потоку, строка помечается ошибкой с числом
лишних.

## Антибот-проверка

Это главное ограничение, и оно не программное: магазин может вместо карточки
товара отдать страницу проверки (у Ozon вкладка называется `Antibot Captcha`).
Тогда в логе будет исход `blocked`.

Что делает программа:

- **Распознаёт проверку** по заголовку вкладки и по тексту страницы, и пишет
  честный диагноз `blocked`, а не «кнопка не найдена».
- **Заходит на главную** перед первым товаром: сессия начинается как у
  человека, а не с прямого попадания на карточку.
- **Даёт пройти капчу руками.** Со снятой галкой «Headless» поток
  останавливается на проверке, пишет в лог, в каком окне её решить, и ждёт
  заданное в «Ждать капчу, с» время. Как только проверка снята, поток
  доделывает тот товар, на котором споткнулся, и идёт дальше.
- **Снимает экономию трафика на время проверки.** Пазл в капче — картинка, и
  с включённой блокировкой виджет крутит спиннер бесконечно. Поэтому блокировка
  сделана только через CDP (её можно выключить на ходу), а не флагами запуска
  Chrome, которые обратно уже не включить. При появлении проверки блокировка
  снимается, страница перезагружается, и после прохождения экономия
  возвращается.
- **Подсказывает по итогам**, что менять, если проверок было много.

Что помогает, по убыванию действенности: снять «Headless» → уменьшить число
потоков до 1 → снять «Без картинок» → войти в аккаунт через «Открыть корзину»
и немного полистать сайт, чтобы профиль стал «обжитым».

Гарантий здесь нет: пройдёт ли автоматизация проверку, решает магазин.

## Что стоит иметь в виду

- Много параллельных headless-сессий с одного IP повышают шанс поймать
  проверку — начните с 1–2 потоков и поднимайте, глядя на долю `blocked`.
- Селекторы завязаны на текущую вёрстку магазинов. При массовых ошибках
  `Кнопка «В корзину» не найдена` или `Кнопка «Поделиться» не найдена` правьте
  соответствующий `Market` в `markets.py` — весь остальной код это не затронет.
- Чтение буфера обмена в headless срабатывает не на всех сборках Chrome. Если
  ссылка стабильно не достаётся, снимите галку «Headless» — в видимом окне этот
  путь надёжнее.
- Chrome не даёт двум процессам держать один `user-data-dir`, поэтому
  «Открыть корзину» доступно только после остановки сборки.
