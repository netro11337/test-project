# Остатки Ozon и Wildberries из Google-таблицы — без API

Скрипт для Google Таблиц: берёт ваш лист «код товара → сколько должно быть»
и готовит файл остатков, который остаётся только загрузить в личный кабинет.

Поддерживаются Ozon (по артикулу продавца) и Wildberries (по баркоду), в любом
количестве кабинетов — за один запуск получается по файлу на каждый.

API не используется: ключи не нужны, доступов ни у кого не запрашивается.
Единственное ручное действие — загрузить готовые файлы в ЛК.

## Как это работает

Вы один раз скачиваете из каждого кабинета штатный шаблон остатков и кладёте
его на Google Диск. Шаблон приходит пустым.

**Ozon** — четыре колонки, под заголовком одна-две строки с подсказками,
данные идут с четвёртой строки:

| Название склада (идентификатор склада) | Артикул | Название товара | Доступно на складе, шт |
|---|---|---|---|
| Редактируемое обязательное | Редактируемое обязательное | Редактируемое | Редактируемое обязательное |
| Выберите из выпадающего списка склад… | Укажите артикул товара… | Укажите название товара | Укажите количество… |

**Wildberries** — две колонки и никаких подсказок:

| Баркод | Количество |
|---|---|

Склад в файле WB не указывается: там вы выбираете его в интерфейсе перед
загрузкой, поэтому и колонки такой нет.

Дальше скрипт находит колонки по их названиям, пропускает служебные строки
и дописывает ваши остатки с первой пустой строки. Формат остаётся ровно тот,
который ждёт площадка, — скрипт ничего не выдумывает и подсказки не затирает.

Название склада для Ozon берётся из выпадающего списка самого шаблона: если
склад один, он подставится сам.

Есть и запасной режим — «Собрать файл(ы) с нуля», без шаблона. Он строит файл
по названиям колонок из настроек. Нужен, только если шаблон недоступен.

## Установка

### 1. Листы с данными

На каждый магазин — свой лист с двумя колонками:

| sku | остаток |
|---|---|
| ART-001 | 12 |
| ART-002 | 0 |

Для Ozon в первой колонке артикул продавца (не SKU Ozon), для WB — баркод.
Заголовки ищутся в первых 10 строках; регистр и лишние пробелы не важны,
подойдут и `sku`, и `Артикул`, и `Баркод`.

### 2. Папки на Google Диске

Нужны две: куда вы кладёте шаблоны и куда складывать готовые файлы.
ID папки — часть её адреса: `drive.google.com/drive/folders/<ID>`.

### 3. Шаблоны из личных кабинетов

Ozon: **Управление логистикой → три точки на карточке склада → Управление
остатками → «Скачать отчёт в XLS»**.

Скачанные файлы положите в папку шаблонов как есть, не открывая и не
пересохраняя. Перескачивать их не нужно: шаблон пустой и от появления новых
товаров не устаревает.

### 4. Код

**Расширения → Apps Script** в вашей таблице. Скопируйте целиком
[`apps-script/single-file/OzonOstatki.gs`](apps-script/single-file/OzonOstatki.gs)
и вставьте в `Код.gs` вместо заготовки. Затем слева **Сервисы → + →
Drive API → v3 → Добавить** — без этого скрипт не сможет прочитать шаблон.

Если удобнее держать код разбитым по файлам, перенесите `Config.gs`,
`Utils.gs`, `Fill.gs`, `Build.gs`, `Menu.gs` из `apps-script/` как отдельные
файлы скрипта, а в настройках проекта включите показ `appsscript.json`
и замените его содержимым из репозитория.

Через [clasp](https://github.com/google/clasp):

```bash
clasp clone <SCRIPT_ID>
cp apps-script/*.gs apps-script/appsscript.json .
clasp push
```

Однофайловая версия собирается командой `bash tools/build-single-file.sh` —
править нужно исходники в `apps-script/`, а не собранный результат.

### 5. Настройки

Всё правится в одном месте — в начале кода (файл `Config.gs`).

Общее для всех магазинов:

```js
OUTPUT_FOLDER_ID: '...',   // папка для готовых файлов
EMAIL_TO: '',              // куда присылать файлы; пусто — не отправлять
DAILY_HOUR: 8,             // час автозапуска
```

Магазины:

```js
SHOPS: [
  { name: 'НАПАЛМ',    sheet: 'НАПАЛМ ОСТАТКИ',    templateFolderId: '1aaa...', templateFile: 'НАПАЛМ' },
  { name: 'ГМС',       sheet: 'ГМС ОСТАТКИ',       templateFolderId: '1aaa...', templateFile: 'ГМС' },
  { name: 'Енидорцев', sheet: 'Енидорцев остатки', templateFolderId: '1aaa...', templateFile: 'Енидорцев' },
  { name: 'ВБ',        sheet: 'ВБ ОСТАТКИ',        templateFolderId: '1aaa...', templateFile: 'ВБ', platform: 'wb' }
],
```

- `name` — свободная подпись: идёт в отчёт, в лог и в имя файла.
- `sheet` — лист таблицы с остатками этого магазина.
- `templateFolderId` — папка с его шаблоном.
- `templateFile` — часть имени файла шаблона. Нужен, только если шаблоны
  нескольких магазинов лежат в одной папке.
- `platform` — `'wb'` для Wildberries, для Ozon можно не писать.
- `warehouse` — склад; можно не указывать, если в кабинете он один.

Если магазин один, `SHOPS` можно оставить пустым — тогда работают
`SOURCE_SHEET` и `TEMPLATE_FOLDER_ID` из общих настроек.

## Как добавить ещё один магазин

Три шага, кода не касается:

1. Новый лист в таблице с колонками «код товара / остаток».
2. Шаблон из его кабинета — в папку шаблонов, с именем магазина в названии
   файла (`РОМАШКА шаблон.xlsx`).
3. Строка в `SHOPS` по образцу соседних: свои `name`, `sheet`, `templateFile`;
   `platform: 'wb'` — если это Wildberries.

Дальше **«Проверить данные»** и **«Проверить шаблоны»** — они скажут, если
лист не найден или шаблон подхватился не тот.

Частая ошибка при копировании строки — забыть поправить `name` или
`templateFile`. Скрипт такое не пропускает: одинаковые имена магазинов дали бы
одинаковые имена файлов, а одинаковый `templateFile` означал бы, что два
магазина берут один шаблон.

## Привязка магазина к шаблону

Держится только на настройках: скрипт берёт файл из указанной папки (и с
указанным `templateFile`), а определить по содержимому, из какого он кабинета,
не может — шаблоны разных кабинетов отличаются лишь списком складов.

Две страховки:

- **«Проверить шаблоны»** в меню — показывает по каждому магазину, какой файл
  подхватился и какие склады в нём лежат. Файлов не создаёт.
- **`warehouse` в настройках** — тогда чужой шаблон не пройдёт молча: скрипт
  остановится с сообщением, что такого склада в нём нет. Цифры идентификатора
  знать не нужно, хватит названия или его узнаваемой части.

Свалить шаблоны в одну папку и не указать `templateFile` нельзя — непонятно,
чей брать. Скрипт на этом останавливается. Одинаковые `templateFile` у двух
магазинов он тоже не пропустит.

## Ежедневная работа

1. Обновляете остатки на листах.
2. **Остатки → Заполнить шаблон(ы) из ЛК** (или ждёте автозапуска).
3. Забираете готовые файлы из папки на Диске или из письма.
4. Загружаете каждый в свой кабинет и жмёте «Обновить остатки».

Меню `Остатки` появляется в таблице после перезагрузки страницы.

- **«Проверить данные»** — прогоняет листы без создания файлов: сколько
  позиций, сколько нулей, есть ли ошибки в данных.
- **«Проверить шаблоны»** — что подхватилось из папок и какие там склады.
- **«Включить ежедневный запуск»** — файлы готовятся сами к нужному часу.

Готовые файлы называются `ostatki-<площадка>-<магазин>-<дата>.xlsx`. Если один
магазин не отработал, остальные всё равно готовятся — сбойный попадёт в отчёт
и в лист `Лог`, куда пишется каждый запуск.

## Важно: что попадает в файл

Только те коды товаров, которые есть в вашем листе. Площадка обновит остатки
именно по ним, остальное в кабинете останется как было.

Чтобы товар обнулился, он должен быть в листе со значением `0`. Просто убрать
строку недостаточно: площадка про него ничего не узнает и оставит прежний
остаток.

Настройка `MISSING_SKU_ACTION` касается только шаблонов, которые приходят уже
заполненными: `'keep'` — не трогать такие строки, `'zero'` — обнулить.
Для обычного пустого шаблона она ни на что не влияет.

## Что проверить на первом запуске

- Откройте готовый файл: у Ozon строки с подсказками должны остаться
  нетронутыми, товары — начинаться с 4-й строки, в первой колонке склад.
  У WB товары идут со 2-й строки.
- Загрузите файл в ЛК и убедитесь, что он принят без ошибок.
- Если скрипт пишет, что не нашёл колонки, — откройте шаблон, посмотрите их
  точные названия и допишите в `HEADER_ALIASES`.

## Ограничения

- Ozon — только **FBS/rFBS**. Остатки FBO лежат на складе Ozon и файлом не
  меняются, только поставкой.
- Файлы всё равно загружаются в кабинет руками. Полностью автоматическим
  процесс делает только API площадки.
- У WB склад выбирается в интерфейсе при загрузке — скрипт на это не влияет.
