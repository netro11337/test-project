# Остатки Ozon FBS из Google-таблицы — без Seller API

Скрипт для Google Таблиц: берёт ваш лист `sku → сколько должно быть` и готовит
файл остатков, который остаётся только загрузить в личный кабинет Ozon Seller.

Seller API не используется — ключи не нужны, доступов ни у кого не запрашивается.
Единственное ручное действие — загрузить готовый файл в ЛК (около минуты в день).

## Как это работает

Есть два режима.

**Режим А — «Заполнить шаблон из ЛК» (основной).**
Вы один раз скачиваете из личного кабинета штатный шаблон остатков и кладёте его
в папку на Google Диске. Каждый день скрипт открывает этот шаблон, находит в нём
колонки артикула и количества, проставляет ваши остатки и сохраняет готовый файл.
Формат остаётся ровно тот, который ждёт Ozon, — скрипт ничего не выдумывает.

**Режим Б — «Собрать файл с нуля» (запасной).**
Файл собирается из трёх колонок: склад, артикул, количество. Названия колонок
задаются в настройках. Нужен, если шаблон по какой-то причине недоступен.

## Установка

### 1. Лист с данными

В вашей таблице должен быть лист (по умолчанию `Остатки`) с двумя колонками:

| sku      | остаток |
|----------|---------|
| ART-001  | 12      |
| ART-002  | 0       |

Заголовки ищутся в первых 10 строках, регистр и лишние пробелы не важны.
Артикул — тот же, что в личном кабинете (артикул продавца / `offer_id`).

### 2. Папки на Google Диске

Создайте две папки (можно одну на оба пункта):

- куда вы кладёте скачанный из ЛК шаблон;
- куда складывать готовые файлы.

ID папки — это часть адреса: `drive.google.com/drive/folders/<ID>`.

### 3. Шаблон из личного кабинета

В Ozon Seller: **Управление логистикой → три точки на карточке склада →
Управление остатками → «Скачать отчёт в XLS»**. Положите скачанный файл в первую
папку. Обновлять его нужно, только когда меняется ассортимент.

### 4. Код

**Расширения → Apps Script**, затем перенесите содержимое папки `apps-script/`:

- `Config.gs`, `Utils.gs`, `Fill.gs`, `Build.gs`, `Menu.gs` — как отдельные файлы скрипта;
- в **Настройках проекта** включите «Показывать файл манифеста `appsscript.json`»
  и замените его содержимым из репозитория (там подключается Drive API — без него
  скрипт не сможет прочитать шаблон).

Либо, если пользуетесь [clasp](https://github.com/google/clasp):

```bash
clasp clone <SCRIPT_ID>
cp apps-script/* .
clasp push
```

### 5. Настройки

Откройте `Config.gs` и заполните как минимум:

```js
TEMPLATE_FOLDER_ID: '...',   // папка со скачанным шаблоном
OUTPUT_FOLDER_ID:   '...',   // папка для готовых файлов
```

Остальное — по желанию: `EMAIL_TO` (куда присылать готовый файл),
`DAILY_HOUR` (час автозапуска), `SOURCE_SHEET`, названия колонок.

Отдельно обратите внимание на `MISSING_SKU_ACTION` — что делать с товарами,
которые есть в шаблоне Ozon, но отсутствуют в вашей таблице:

- `'keep'` (по умолчанию) — не трогать их остатки;
- `'zero'` — проставить 0. Ставьте это значение, только если ваша таблица
  содержит **все** товары: иначе всё, что в неё не попало, уедет в ноль.

## Ежедневная работа

1. Обновляете остатки в таблице.
2. **Ozon → Заполнить шаблон из ЛК** (или ждёте автозапуска).
3. Забираете готовый файл из папки на Диске или из письма.
4. Загружаете его в ЛК и жмёте **«Обновить остатки»**.

Меню `Ozon` появляется в таблице после перезагрузки страницы. Пункт
**«Проверить данные»** прогоняет лист без создания файлов — показывает количество
позиций, нули и ошибки в данных.

**«Включить ежедневный запуск»** ставит триггер: файл готовится сам к нужному
часу, вам остаётся только загрузить его.

Каждый запуск пишется в лист `Лог`: сколько позиций обновлено, сколько обнулено,
какие SKU из таблицы не нашлись в шаблоне.

## Что стоит проверить на первом запуске

- Откройте готовый файл глазами и сверьте с шаблоном: те же колонки, те же
  артикулы, количества на месте.
- Загрузите его в ЛК и убедитесь, что Ozon принял файл без ошибок. Если ЛК ругается
  на формат — скорее всего, дело в конвертации `.xls → .xlsx`; тогда скачайте
  шаблон в `.xlsx`, если такая опция есть, и положите в папку его.
- Если скрипт пишет «не найден лист с колонками артикула и количества» — откройте
  шаблон, посмотрите точные названия колонок и допишите их в `HEADER_ALIASES`
  в `Config.gs`.

## Ограничения

- Только **FBS/rFBS**. Остатки FBO лежат на складе Ozon и файлом не меняются —
  только поставкой.
- Файл всё равно загружается в ЛК руками. Полностью автоматическим процесс
  становится только через Seller API (метод `/v2/products/stocks`) — код под это
  пишется примерно за час, если организационно такой вариант когда-нибудь
  окажется возможен.
